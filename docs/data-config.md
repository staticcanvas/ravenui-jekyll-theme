Jekyll loads every file under `_data/` into the global `site.data` object at build time. RavenUI components expose a `data_source` parameter that accepts the filename (without extension) of any file in `_data/`, making it straightforward to drive components from structured data without writing custom Liquid loops on each page.

{% include comps/heading.html tag="h2" text="File Formats Supported" icon="database" size=20 %}

Jekyll natively parses all four common structured data formats. Each format produces the same Liquid-accessible data structure once loaded.

| Format | Extension | Notes |
| :--- | :--- | :--- |
| YAML | `.yml` / `.yaml` | Most common. Human-readable, supports comments, preferred for navigation, releases, authors. |
| JSON | `.json` | Ideal when data is generated programmatically or sourced from external APIs. |
| CSV | `.csv` | First row becomes the key names. Each subsequent row is a hash. No nested structures. |
| TSV | `.tsv` | Same as CSV but tab-delimited. Less common; supported natively since Jekyll 3.3. |

{% include comps/callout.html type="note" title="YAML is the Standard" content="Unless data is generated from a CI script or external source, prefer YAML. It supports comments, multi-line strings, and anchors — none of which are available in JSON or CSV." %}

---

{% include comps/heading.html tag="h2" text="Referencing Data in Components" icon="link" size=20 %}

### **Simple Filename Reference**

The `data_source` parameter accepts the filename without its extension. Jekyll resolves the file regardless of whether it is `.yml`, `.json`, `.csv`, or `.tsv`.

```liquid
{% include comps/datatable.html
  data_source="releases"
  headers="tag_name:Version,name:Name,published_at:Published" %}
```

This maps to `_data/releases.yml` and passes the resulting array to the datatable component.

### **Dot-Separated Nested Path**

For files organised in subfolders, use dot-notation to traverse the path:

```liquid
{% include comps/datatable.html
  data_source="products.accessories"
  headers="name:Name,sku:SKU,price:Price" %}
```

This maps to `_data/products/accessories.yml`. See [Data Subfolders](/data-subfolders/) for full details on subfolder organisation.

---

{% include comps/heading.html tag="h2" text="YAML Data Files" icon="file-text" size=20 %}

YAML is the most widely used format in Jekyll projects. It supports arrays, named objects, multi-line strings, and inline comments.

### **Array Format**

```yaml
# _data/authors.yml
- name: Ada Lovelace
  role: Lead Engineer
  github: ada

- name: Grace Hopper
  role: Compiler Architect
  github: grace
```

Access in Liquid:

```liquid
{% for author in site.data.authors %}
  <p>{{ author.name }} — {{ author.role }}</p>
{% endfor %}
```

### **Named Object Format**

```yaml
# _data/site_meta.yml
title: RavenUI Docs
version: 1.3.4
maintainer: staticcanvas
```

Access a specific key:

```liquid
{{ site.data.site_meta.version }}
```

---

{% include comps/heading.html tag="h2" text="JSON Data Files" icon="braces" size=20 %}

JSON files are accessed identically to YAML files through `site.data`. They are the natural choice when data is generated by a script or pulled from an external API response.

```json
// _data/packages.json
[
  { "name": "ravenui-core", "version": "1.3.4", "type": "theme", "status": "stable" },
  { "name": "ravenui-icons", "version": "2.1.0", "type": "plugin", "status": "stable" }
]
```

Component usage:

```liquid
{% include comps/datatable.html
  data_source="packages"
  headers="name:Package,version:Version,type:Type,status:Status" %}
```

See [JSON Data Files](/data-json/) for a dedicated reference covering nested objects, CI generation, and validation.

---

{% include comps/heading.html tag="h2" text="CSV Data Files" icon="table" size=20 %}

Jekyll parses CSV files into an array of hashes, using the first row as the key names. This makes CSV files immediately compatible with any component that accepts an array `data_source`.

```csv
name,version,downloads,status
ravenui-core,1.3.4,12048,stable
ravenui-icons,2.1.0,8820,stable
```

Component usage (identical syntax to YAML/JSON):

```liquid
{% include comps/datatable.html
  data_source="packages_csv"
  headers="name:Package,version:Version,downloads:Downloads,status:Status" %}
```

{% include comps/callout.html type="note" title="CSV Limitations" content="CSV does not support nested structures or multi-line values. For any data with hierarchical relationships, use YAML or JSON instead." %}

---

{% include comps/heading.html tag="h2" text="TSV Data Files" icon="columns" size=20 %}

TSV (Tab-Separated Values) files behave identically to CSV but use tab characters as the delimiter. They are useful when field values contain commas and escaping would be cumbersome.

```tsv
name	version	status
ravenui-core	1.3.4	stable
ravenui-icons	2.1.0	stable
```

Access and component usage follows the same pattern as CSV. TSV is the least common format in Jekyll projects; prefer YAML or JSON for new data files unless you are importing from an existing TSV source.

---

{% include comps/heading.html tag="h2" text="Subfolder Organisation" icon="folder" size=20 %}

Files nested inside subdirectories of `_data/` are accessed using dot-notation: `site.data.<subfolder>.<filename>`. This is the recommended approach for projects with many data files.

```liquid
{{ site.data.products.accessories | map: "name" | join: ", " }}
```

The `data_source` parameter supports the same dot-notation:

```liquid
{% include comps/datatable.html data_source="products.accessories" headers="name:Name,sku:SKU" %}
```

See [Data Subfolders](/data-subfolders/) for directory structure examples, naming conventions, and caveats.

---

{% include comps/heading.html tag="h2" text="Inline Data vs. Data Files" icon="toggle-left" size=20 %}

Several RavenUI components accept both a `data_source` parameter (file-backed) and an `items` parameter (inline array defined in Liquid). Use the following guidelines to decide:

| Approach | When to Use |
| :--- | :--- |
| `data_source="filename"` | Data is reused across multiple pages, managed separately, or generated by CI. |
| `items=array` | Data is unique to a single page, small in size, or derived from page front matter. |

```liquid
{% assign my_items = page.features %}
{% include comps/feature-grid.html items=my_items %}
```

Prefer `data_source` for any dataset that may change independently of page content; it keeps page files clean and data maintainable in one place.
